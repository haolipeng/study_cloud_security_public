Suricata TCP 流重组 — 形象版

比喻:乱序快递 → 货架排序 → 传送带输送 → 三个读头消费 · stream-tcp-*.c

核心比喻

  • • 📦 TCP段 = 快递包裹(可能乱序)
  • • 🗂️ 红黑树 = 智能货架(自动按单号排)
  • • 🎞️ StreamingBuffer = 传送带(连续输送)
  • • 👁️ 三读头 = 不同工序同时读取

为什么分两层?

  • • 货架只存"单号+位置",不存货物
  • • 真实货物(payload)在传送带上
  • • 乱序段先上货架,等前面到齐再上传送带
  • • 传送带始终连续,下游不用处理乱序

base_seq 滑动机制

  • • base_seq = 传送带起点
  • • 有 gap(断开) → base_seq 不动
  • • gap 补齐 → base_seq 右移
  • • 最慢读头决定左侧何时回收
